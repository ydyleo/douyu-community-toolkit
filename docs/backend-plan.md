# 前后端分离决策

> 2026-07-30：前端与后端改为两个并列项目，允许前端公开推送 GitHub，后端保持私有。

## 项目边界

- `主播烂梗档案馆`：Nuxt 纯前端、静态资源、油猴脚本和公开 API 类型。
- `主播烂梗档案馆-api`：Fastify API、管理员认证、PostgreSQL、数据库迁移和生产容器。
- 前端只通过 `NUXT_PUBLIC_API_BASE` 访问后端，不直接接触数据库。

## 部署边界

首发时两个项目可以部署在同一台云服务器的不同容器中，也可以把前端放在静态托管服务；这不影响代码和发布上的前后端分离。

推荐公网入口：

- `https://9765366.cn`：前端网站。
- `https://9765366.cn/api`：后端 API，由公网入口反向代理到内部 API 容器。
- PostgreSQL：仅允许后端通过私有网络访问，不开放公网端口。

## 后续演进

- 表情包元数据、下载统计和签名上传归后端管理。
- 图片与音频迁移到 OSS，数据库只保存对象键和元数据。
- Redis 首发不作为依赖，出现明显刷量或多实例部署后再增加。
- 标签合并由管理员发起，后端在同一事务中更新公开烂梗和投稿记录，并统一执行标签规范化与去重。
- 待审烂梗查重使用文字片段、包含关系、标签交集和分类综合评分；只向管理员提供可解释提示，不自动拒绝投稿。
- 公开烂梗的编辑和删除功能仍需补充到管理后台。
