# 发布流程

GitHub 推送与生产发布是两件独立的事。代码进入仓库不会自动更新 `9765366.cn`；只有在服务器上重建生产容器，正式网站和稳定版油猴脚本才会变化。

## 日常开发

1. 从 `main` 创建 `feature/...` 分支。
2. 在本地启动 PostgreSQL、API 和 Nuxt；数据库迁移只对本地数据库执行。
3. 执行 `npm run release:check`，后端执行 `npm run typecheck` 和相关冒烟测试。
4. 从本地地址安装候选版油猴脚本，验证搜索、复制、填入、发送、更新提示和统计上报。
5. 推送功能分支，让 GitHub Actions 再做一次独立构建；此时不部署生产。

## 正式发布

1. 候选版本经人工确认后合并到 `main`。
2. 涉及数据库迁移时先创建生产数据库备份，并核对回退脚本。
3. 先部署向后兼容的数据库迁移与 API，再发布前端和油猴稳定版。
4. 检查首页、后台、健康接口和油猴安装地址，观察服务器日志与关键统计。
5. 发现问题时停止继续发布；前端和油猴回退到上一提交，数据库只在确认安全后执行对应回退脚本。

## 油猴版本规则

- 网站只公开一份稳定版安装脚本，历史版本保留更新说明和 Git 提交，不提供旧版安装入口。
- 普通功能或修复提高补丁版本，例如 `0.8.0` 到 `0.8.1`。
- 明显新增能力提高次版本，例如 `0.8.x` 到 `0.9.0`。
- 每次改动版本号时必须同步 `release.json`，构建检查会阻止两者不一致的版本发布。
